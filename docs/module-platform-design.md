# CRM 模块扩展设计

## 目标和当前状态

用户可以让 Pi 提出新的业务页面或后台同步功能。页面模块在侧边栏提供入口；后台模块不必有侧边栏入口。两种模块可以同时存在于同一个扩展中。

桌面导航包含宿主内置模块和当前用户安装的自定义页面。创造模式可生成静态卡片页面的 JSON，宿主负责预览、校验和按当前用户与企业保存；同一标识可预览更新。尚不具备任意代码隔离、Notion 授权或飞书同步。

## 模块清单

每个模块使用版本化清单声明 `id`、名称、版本、最低宿主版本、页面入口、后台任务入口和所需权限。页面和后台入口各自可选，至少存在一个。标识必须唯一；清单中的字段、入口、权限、版本和资源大小由宿主验证。清单是声明，不会自动授权。

页面模块初版优先采用受限的声明式页面：Pi 生成页面配置，宿主用内置组件渲染表格、表单和操作。任意 React/JavaScript、远程脚本和内嵌网站不默认执行。Notion 页面若需完整嵌入，必须单独确认第三方网站的嵌入限制、登录方式和安全隔离；不假设可以用 iframe 直接实现。

后台模块声明触发方式、输入来源、目标适配器和可执行操作，但清单自身不能启动任意进程或自动向第三方发送数据。同步由宿主提供的受控执行器调用 CRM 和目标应用适配器。

## 创建、预览和发布

1. 用户告诉 Pi 所需功能，Pi 生成候选模块清单和页面配置或同步方案。
2. 宿主校验结构、允许的组件、权限和目标；文件变更先执行 dry run，给出变更预览，不修改正式文件。
3. 用户查看页面预览、目标、数据范围和权限后，按权限策略批准安装与启用。正式写入前重新校验目标路径及文件版本。
4. 宿主记录版本和启用状态，加载已经批准的配置；停用后取消该模块的任务和访问能力，提供版本回滚。

当前没有可靠的文件系统隔离，不能开放 Shell、任意文件工具或未经隔离的第三方代码。Pi 提出的内容均视为不可信输入；提示词不承担权限保护。

## 权限和身份

CRM 数据继续通过现有 FastAPI 访问，使用当前用户的服务端认证和对象级授权。模块不能指定用户身份或提升权限；申请的能力和用户实际权限取交集。页面只显示当前用户能访问的内容，权限变化或登出时清理相关缓存并停止任务。

第三方账号由用户在连接设置中授权；凭证由宿主调用操作系统加密能力管理，不交给页面或模型。每个模块仅获得具体连接和操作的授权，目标应用的数据传出范围需明确展示。确认安装不等于批准每次高风险发送；对于创建、覆盖或发送等外部副作用，执行前按具体风险执行确认策略。

## 数据同步

同步任务应明确记录来源企业、发起人、目标连接、字段映射、方向、过滤条件、触发频率和运行状态。先提供预览和手动执行，再考虑定时；Pi 不绕过宿主直接写 PostgreSQL。

执行时按原发起人的当前权限重新获取 CRM 数据。使用稳定的业务标识和目标记录映射判断新增或更新；针对目标平台的真实接口设计幂等或去重。超时结果不确定时先查询目标，无法确定则停在待处理，不盲目重试。删除、权限回收、字段变更、冲突和部分失败都要有明确策略，不能默认覆盖第三方数据。平台权限或令牌失效后暂停任务并提示用户重新授权。

CRM 服务端 PostgreSQL 不新增表；当前静态页面配置以本地 JSON 文件按服务地址、企业和用户隔离。未来同步游标及任务状态需要合适的本地持久化。离线设备无法保证在另一台电脑上执行或同步状态一致；若以后需要跨设备可靠调度或集中管理，需要另行设计服务端持久化和授权方案。

## 交付顺序和验收

1. 实现模块清单校验、版本管理、启停与侧边栏注册；现有业务页面保持可用。使用不接触外部账号的本地页面示例验证。
2. 实现 Pi 生成声明式页面配置、dry run 和预览。验证非法配置、路径穿越、权限升级、退出后缓存清理及版本回滚。
3. 实现受控连接管理和后台执行器，以本地模拟目标验证授权、幂等、超时、重试、权限撤销、任务恢复和日志脱敏。
4. 根据选定的 Notion / 飞书具体场景，实现对应官方接口适配器和真实账号授权；真实服务对接、配额和写入语义以其官方文档和实际测试为准。

不将模拟连接或示例同步显示为真实接入成功。跨设备后台常驻同步、任意代码插件和第三方网页直接嵌入不是第一版默认能力。
# 本地记录的单实例边界

桌面主进程通过 Electron 单实例锁限制同一应用数据目录同时运行一个实例；第二次启动会激活已有窗口。应用内本地记录的修改、删除还检查版本。真实 Electron 测试验证了相同 userData 下第二个进程无法取得锁。这不防止其他程序直接修改文件，也不是跨设备或多用户数据库事务；不要绕过应用并发写入这些文件。
