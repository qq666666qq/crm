# Agent 中心集成状态与边界

## 用户补充的文件修改与浏览器要求

- Agent 的文件修改必须先由程序进行 dry run（试运行）：读取授权路径的当前版本，在内存或受限临时副本生成变更预览，检查目标、路径、敏感文件、符号链接和可写权限；试运行阶段不能写入真实目标，也不能执行可能改变外部状态的命令。预览结果应标明失败或待确认的检查，不能把预览成功当作写入一定成功。
- 提交写入前应重新验证文件版本和路径归属，版本已变更则拒绝并重新生成预览。实际写入采用临时文件和原子替换（平台支持时），保留必要的回滚信息；文件修改的审批级别按未来具体权限策略执行，不能假定每次都必须人工确认。
- dry run 是预览和校验机制，不是操作系统沙盒；真正执行仍需受控工具及必要的进程隔离。Shell、浏览器提交和联网副作用不能靠一个标有 dry run 的参数保证安全。
- 浏览器自动化仅允许通过 ego(lite) 适配器调用 ego(lite)，不提供其他浏览器操控路径，也不通过任意 Shell 绕过。安装缺失时应提示用户从 [ego(lite) Windows 官方指南](https://www.egolite.ai/document/en/docs/windows/quick-start) 安装和配置；安装及浏览器登录数据导入均应由用户在界面中审阅。当前仅为要求记录，适配器、安装检测和执行限制尚未实现。
- ego(lite) 的 Space 可以使用 ego(lite) 内已有登录状态，不能将 Space 当成账号、文件系统或网络权限沙盒。模型能看到的页面内容可能发送给模型服务商；动作能力应由程序而不是仅由提示词限制，提交、发送及其他有副作用的操作须按权限和确认策略处理。
- 桌面端现提供 Agent 中心安装引导入口及固定的官方指南链接；它是静态安装引导，不自动安装，也不能检测安装或连接状态；Agent 对话另有入口。官方 Windows 安装需用户完成首次设置；待 Agent 对话和受控浏览器适配器实现后再提供交互式协助及连接测试。

## 已核实

- Pi Durable 固定 `@earendil-works/pi-durable`、`pi-ai`、`chord` 1.4.0。Electron 使用 43.8.4；已在真实 Electron 工作进程中验证初始化及加密会话关闭后重开。
- SDK SQLite 文档说明一个进程拥有存储，不提供跨进程锁；WAL 使用 synchronous=NORMAL，进程崩溃恢复与主机断电保证不同。不得让多个 Worker 同时打开同一文件。参考 [Pi Durable README](https://github.com/earendil-works/pi/blob/main/packages/durable/README.md)。
- 独立 Worker 已接入 Electron，支持对话、线索商机、RAG 和创造预设。CRM 只读工具通过主进程限定路径并使用当前用户身份。真实模型已使用虚构 CRM 数据验证工具调用；真实模型经桌面端访问实际 CRM 的完整链路尚未验证。Worker 不是操作系统沙盒。
- 旧的自建 Skill 自演进实现已移除。当前另有基于 Pi 的记忆和 Skill 沉淀流程：满足对话和工具调用阈值后由用户触发生成，模型以温度 0 复审，再由用户确认发布或拒绝，并支持版本回滚。聊天左侧可为每个会话选择最多五个已发布技能，选择会决定 Pi 实际收到哪些技能参考；未设置时默认选择最近五个。它与旧的 Harness² 风格测试套件及聊天回答重跑是不同流程，不应混称为官方 Harness²。

## Accio 功能迁移现状

- 桌面端默认使用系统保护密钥的加密 Pi 会话，记忆库与 Pi 共用数据库；旧数据库迁移前保留源文件，已有目标库时提示用户且不自动合并。记忆提取、轮末反思、会话前缀和 Skill 提示接入 Pi 任务，记忆按本地账号范围隔离。累计八次未补写的请求后，空闲十分钟可触发补写；程序重新检查是否仍是最新请求和来源权限。
- 记忆提取用关键词查找相似已有记忆，模型给出重复、冲突、不同或不确定的意见；无法判断时交由用户确认。相同类别且正文完全相同的待确认记忆可合并来源，仍须人工确认；语义相似的不同表述保留供人核对。管理界面可分页查看记忆与 Pi 中的来源文字，并再次检查来源权限。相似词检索和模型判断不能保证找到所有语义冲突，也不能证明内容真实。
- 本地中文关键词检索可用；用户开启远程语义检索后会向 OpenAI 发送查询及有权限的记忆内容，可设置该服务支持的语义模型。Pi 后台任务分批建立索引，切换模型后重建，重启后恢复；未配置模型或服务异常时等待并重试，查询失败时降级为关键词检索。真实服务连接仍需用户配置并验证。
- 从聊天回答重跑时，Pi 从该轮之前建立分支，只能回放参数完全匹配且仍有权限的历史 CRM 查询和个人记忆查询。AI 比较会收到长度限制内的可核验工具结果，超长或不可用结果会标明；相同参数存在不同结果、未记录的调用或其他类型工具不能安全回放。缺失的轨迹不代表完成验证。Pi 保存任务进度；中断后等待模型可用并重新检查来源，再从原回答重新开始一次安全尝试，可能重复调用模型，但不会重复执行真实业务操作。AI 比较意见和人工选择保存在当前加密 Pi 会话中，来源失权后不能再次读取；选择不会自动修改原对话或发布 Skill。
- Langfuse 导出保留可读对话、每次模型调用和工具原文，过滤凭据及密文字段，不上传模型密钥、密钥片段或其指纹。普通文本中粘贴的秘密无法保证自动识别。
- 使用用户提供的本机兼容模型接口和虚构数据，已分别验证 CRM 模拟查询、记忆提取与反思、Skill 生成复审、自进化比较，以及一次带查询结果的安全回放。反思任务在模型调用期间或刚写入记忆后被强制终止，再次启动后均能恢复且只保存一次；Skill 复审中断后可恢复并继续等待人工确认；自进化中断后会等待模型可用，再恢复为一次新的安全尝试。真实 OpenAI 语义检索服务和真实 Langfuse 实例尚未验证。
- 待补：进一步完善跨语言和不同表述的冲突召回及其他工具的安全回放。相近记忆可能生成多条候选，不能仅依赖模型结论自动合并。
- 证据原型只验证所提供快照中有逐字引用、计算 Unicode 位置及进行简单字面检查；它不能证明快照来自真实消息，不能证明字段的隐含语义，也不能代替人工确认。原始快照必须通过未来授权的邮件或消息适配器获得。
- 创建客户公司、联系人、商机、跟进任务、沟通记录、创建线索（人工事实依据）、线索转商机、完成跟进任务及部分公司/联系人/线索/商机字段修改提供主进程审批申请、审核内容校验和固定幂等键。申请按企业和用户保存在本地，并使用系统账户加密；旧明文记录在对应账号访问时迁移。拒绝不调用服务端，未知结果可用同一个键重试。模拟测试覆盖请求、超时及独立进程在模拟服务端提交后被终止：重新登录不会自动重放，用户可用同一键手动重试；模拟目标按该键去重。隔离 PostgreSQL 上的 FastAPI 测试已验证这些 Agent 来源请求的幂等、租户、权限和版本边界；真实模型经桌面审批到真实 CRM 的完整链路仍需端到端验证。现阶段没有真实消息来源适配器，不能把模型文本当成邮件原文。原有内存审批原型没有用于执行这些操作，邮件发送审批尚未接入。
- DeepSeek 提供独立的 [Search 和 Fetch API](https://api-docs.deepseek.com/guides/search/)，使用 bearer 凭证；目前未配置、未调用。搜索结果、网页和模型结论必须分别保存来源。
- [Harness² 官方项目](https://github.com/google-research/harness2)列出的执行器包括 Codex 和 OpenCode，不能假设现有 Pi 插件；其[安装说明](https://github.com/google-research/harness2/blob/main/docs/SETUP.md)要求在 Linux 环境运行相应基准。当前 Windows 桌面尚无 Pi 适配器或隔离执行环境，未集成，也不会自动运行。
- [Langfuse CSV 导入](https://langfuse.com/changelog/2025-01-27-Dataset-Items-csv-upload)由用户映射输入、预期输出和元数据列；桌面端可将用户填写的最多三条测试用例导出为 CSV；导入时需用户映射 input 和 expected_output。尚未验证实际导入，也不自动上传。
- 本地状态日志保存任务编号、开始与结束时间和状态。新产生的详细轨迹另存入 Pi 会话数据库，Langfuse 上传及文件导出会逐页读取数据库；上传状态按账号和目标项目保存，重启后可继续。旧会话可从 Pi 当时保存的消息和工具结果重建，缺失的模型输入或时间会标记为不可用，不能凭空恢复。数据库写入失败时，本次运行的记录会暂存在内存并给出提示。临时会话在关闭后无法恢复。尚未验证真实 Langfuse 实例；中断时间以重启发现中断的时间为准。
- 桌面端默认使用本机加密会话，也可主动切换为关闭后无法恢复的临时会话。加密密钥由当前系统账号保护；旧明文文件不会自动删除。退出或切换账号会停止 Agent 并清除模型配置。

## 未交付

真实消息证据链、全面的 CRM 更新工具、所有任务阶段的崩溃恢复验证、邮件和 WhatsApp、联网搜索、RAG 接口、Harness² 官方仓库适配均未实现；聊天重跑和比较是本项目的独立实现，不能视为官方 Harness² 的完整等价物。真实 Langfuse 实例的端到端上传验证尚未进行。Windows 文件系统和 Shell 沙盒也未实现；不要注册任何文件或 Shell 工具，直到具备经过测试的操作系统隔离。Node 子进程本身不能隔离文件、环境变量或网络。

## 本机模型功能检查

在 `client` 目录运行 `npm run test:pi-live`，需预先通过环境变量提供 `CRM_PI_SMOKE_URL`、`CRM_PI_SMOKE_KEY` 和 `CRM_PI_SMOKE_MODEL`。地址必须是本机 HTTP 接口。脚本并行运行独立的小任务，使用临时会话和虚构客户资料，不访问或写入实际 CRM；它会调用所配置的模型服务。只测某项时可设置 `CRM_PI_SMOKE_CASES`，例如 `自进化轨迹回放`。密钥不要写入仓库。
