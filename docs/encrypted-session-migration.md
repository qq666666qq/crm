# Pi 会话加密与旧数据迁移

桌面端默认将 Pi 会话和记忆保存在本机加密数据库中。数据库密钥由 Electron 的系统安全存储保护，数据按服务地址、企业和用户分别存放。用户也可以主动切换到临时会话，临时会话退出后不会恢复。

启动加密会话时，程序会检查当前账号目录下的旧 `conversations.sqlite`。当加密目标为空时，程序从旧库的一致读取快照复制 Pi 表，核对结构和内容，再启用新库。旧文件及其可能存在的 WAL 文件会保留；中断后可以重试。测试覆盖旧会话复制、错误密钥、重启恢复和 Electron 工作进程启动。

如果加密目标中已有数据，程序不会覆盖或自动合并，会在 Agent 中心提示旧数据尚未合并。旧版按企业和用户标识存储的 `session.sqlite` 属于另一位置，界面可以列出该文件及其 WAL、SHM 的路径和大小，但目前不自动导入。不同服务地址可能使用相同的旧标识，因此不能仅凭路径推断它属于哪一个服务。

## 备份旧数据

1. 在 Agent 中心“对话隐私”查看旧记录位置并记下路径。
2. 退出 CRM 桌面程序，确认没有其他 CRM 进程持有数据库。将主数据库及存在的 `-wal`、`-shm` 文件一起复制到同一个备份目录。
3. 将备份放在经过加密且访问受限的位置；普通文件复制本身不会加密。保留原文件，确认备份可以恢复后再考虑清理。

系统安全存储保护的是当前操作系统账号下的密钥，不能隔离同一系统账号中的恶意进程。旧明文文件和自行制作的备份不会被自动加密或删除。
