# Langfuse 运行记录导出

OTLP 是 OpenTelemetry 传输运行记录的格式。桌面端按 OTLP/HTTP 的 JSON 格式发送可读数据；格式本身不要求加密或解密。服务端地址使用 HTTPS，本机测试地址允许 HTTP。

## 记录范围

- 一次聊天对应一个根记录。Pi 在实际运行时记录每一次模型请求、完整上下文、模型回复、工具名称、参数、返回内容和可用的时间与用量。
- 记忆提取、反思、Skill 候选和复审分别形成后台模型记录，并带有来源会话及请求编号；语义检索的输入和向量结果也有独立记录。
- 聊天自进化的提示词优化、候选执行和结果比较归在一条记录下；旧的 Harness 风格测试套件的模型调用分别记录。它们不是官方 Harness² 的完整实现。
- Langfuse 中每个模型或工具步骤是独立的 observation。不可用的工具计时标为不可用，不能据此推断实际耗时。
- 保留可读原文，不按固定长度截断；按字段名过滤明确的凭据及密文字段。普通文本中用户粘贴的密钥无法保证识别。系统不会为导出专门打开或解密旧会话数据库。

## 使用与限制

在「系统设置 → Langfuse 观测」填写服务地址、项目公钥和密钥，再选择手动上传或运行后自动上传。配置仅在本次登录期间使用。成功上传的记录不会在同一次登录中再次发送；部分接收失败时不会自动整条重传，避免重复。网络中断时，服务端可能已经接收但客户端没有收到结果，手动重试仍可能产生重复。

本次登录期间的记录保存在内存中；退出或切换企业前应上传或导出。旧 `runs.jsonl` 只有编号、时间和状态，无法补出当时未采集的完整模型输入、输出或工具轨迹。本地「导出执行记录」将本次完整轨迹与可用的旧状态记录一起保存。

上传地址为 `{baseUrl}/api/public/otel/v1/traces`，认证使用 Langfuse 项目密钥和 `x-langfuse-ingestion-version: 4`。服务器返回部分拒收时，客户端报告失败。已用模拟接收端、本机模型和真实 Electron 后台进程验证记录内容；尚未用真实 Langfuse 项目核对界面及入库结果。

参考：[Langfuse OTLP 接入及 v4 迁移说明](https://langfuse.com/integrations/native/opentelemetry/migration-to-v4)。
