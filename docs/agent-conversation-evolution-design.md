# Agent 对话内自进化方案

## 目标和界面

Agent 中心以聊天为主。顶部提供新建与历史对话入口；左侧列出可选择的工作方式和工具，明确区分互斥预设与独立工具开关。模型设置、审批和运行记录收进可打开的面板。每条成功的助手回复提供操作菜单，用户可选择自进化。页面主体固定在窗口内，对话和面板各自滚动。

## 一次运行

1. 用户选择某条回复，明确确认是否将其作为满意的基线。未确认时不称其为满意结果。
2. 宿主用该回复的 Pi 条目标识查找对应用户消息及之前的会话前缀，不接受页面传来的基线正文作为可信记录。
3. Pi 在原用户消息之前的条目创建分支；第一条消息没有前缀时创建空分支，并复制该时点的配置。分支不包含选中回答之后的对话。
4. 由独立的 Pi 会话根据原问题生成优化提示词，展示原提示词和候选提示词。不能更改原始会话记录。
5. 在分支使用候选提示词运行；默认不提供真实 CRM 写入、外部发送、任意 Shell 或文件修改工具。涉及工具结果的任务需使用明确标识的回放或模拟数据；若无法重现，标记不可比较。
6. 比较模块汇总基线和候选的回答、可用工具轨迹、失败与耗时，并明确哪些信息缺失。自动评分只作为辅助，不能证明事实正确。用户决定保留哪个结果，发布任何可复用变更仍须单独确认。

## 职责

- Pi：保存会话条目、创建分支、运行模型及工具、记录运行状态。
- 自进化协调模块：选择可信条目、创建运行、施加工具限制、处理取消和失败。
- 比较模块：读取标准化的运行结果，呈现差异，不控制 Pi 生命周期。
- 宿主进程：认证、工具白名单和写入审批；FastAPI 继续执行权限与并发校验。
- 页面：选择条目和展示状态，不作为权限或事实判断依据。

## 历史和隐私

当前桌面端会话使用内存，退出后丢失。多会话先按相同隐私边界实现；跨重启历史必须先实现加密存储与迁移，不能重新启用旧明文数据库。用户和企业切换后不得读取其他范围的历史。模型调用与可选遥测可能向外部发送上下文，界面须明确提示。

## 验证

模拟模型覆盖：中间回答的前缀、不带后续消息、第一条消息、错误条目、模型失败和取消、没有真实写入、原会话不变、人工确认基线、不同会话及账号隔离。前端只检查逻辑和构建，不自动点击真实页面。真实模型、第三方应用及恢复能力分别标注已验证或未验证。

## 现状

现有 Harness² 风格实现会重置执行会话，并没有基于选中回答复用上下文；部分工具选择为空时回退默认工具。它不能直接满足上述流程。当前预设是互斥的，而不是独立的 Skill 开关。以上功能完成前不能声称已实现对话内自进化。
